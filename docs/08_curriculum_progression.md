# 전체 과정 계열성

## 기본 입장

모든 과정에 계열성을 둘 수 있습니다. 다만 모든 과정을 ICT처럼 촘촘한 선후관계로 묶을 필요는 없습니다.

ICT는 조작의 선행 조건이 분명합니다. 클릭을 모르면 저장을 배우기 어렵고, 파일을 모르면 업로드를 이해하기 어렵습니다. 그래서 ICT는 강한 계열성이 필요합니다.

반면 AI 윤리, STEAM 융합, 가치 판단 활동은 반드시 하나의 직선 순서로만 진행하지 않아도 됩니다. 이런 영역은 느슨한 계열성 또는 주제별 매트릭스가 더 적합합니다.

## 계열성의 세 단계

| 유형 | 적용 영역 | 특징 |
| --- | --- | --- |
| 강한 계열성 | ICT, 타자, 코딩 기초 | 앞 단계를 모르면 다음 단계 수행이 어렵다 |
| 중간 계열성 | CT, AI 기초 | 개념은 이어지지만 일부 주제는 독립 미션 가능 |
| 느슨한 계열성 | STEAM, 가치, AI 윤리 | 주제별 선택형 구성이 가능하다 |

## 전체 플랫폼 구조

디지터시 플랫폼은 하나의 긴 직선 코스보다 `대영역 x 체험 모듈` 구조가 적합합니다.

예시:

| 영역 | 기초 | 적용 | 통합 |
| --- | --- | --- | --- |
| ICT | 마우스, 키보드, 창 | 파일, 브라우저, 웹 입력 | 과제 작성과 제출 |
| 타자 | 키 위치, 한글 입력 | 문장 입력, 오타 수정 | 짧은 필사 |
| 코딩 | 순차 | 반복, 선택 | 미로와 문제 해결 |
| CT | 분해, 패턴 | 추상화, 알고리즘 | 효율 비교 |
| AI | 탐색, 분류 감각 | 학습 데이터, 예측 | AI 사용 판단 |
| STEAM | 관찰과 조작 | 데이터와 실험 | 주제형 프로젝트 |
| 가치 | 나와 타인 | 개인정보, 책임 | 딜레마 판단 |

이 구조는 학생에게는 체험 모듈 맵으로 보이고, 교사에게는 교육과정 매트릭스로 보입니다.

## 영역별 계열성 초안

### ICT

가장 강한 계열성을 둡니다. 상위 구조는 세 모듈로 나누고, 각 모듈 내부에서 작은 라운드 계열을 둡니다.

모듈:

- 기능 조작 체험: 마우스 이동, 클릭, 드래그, 짧은 키보드 입력
- OS 동작 체험: 시작 메뉴, 앱 실행, 창 안에서 작업, 저장, 파일 탐색기, 이름 바꾸기, 파일 이동/삭제
- 타자연습: 단어, 띄어쓰기 포함 표현, 짧은 문장, 긴 문장

### 타자

타자는 키 조작과 언어 입력의 계열성을 둡니다.

순서:

1. 한/영 전환
2. 자음과 모음
3. 받침 있는 글자
4. 스페이스와 엔터
5. 백스페이스와 딜리트
6. 쉬프트
7. 단어 입력
8. 짧은 문장
9. 문단 필사
10. 목적 있는 글쓰기

### 코딩

코딩은 명령 구조의 계열성을 둡니다.

순서:

1. 한 명령 실행
2. 여러 명령 순서대로 실행
3. 방향과 위치
4. 반복
5. 조건
6. 반복과 조건 결합
7. 함수 또는 묶음 명령
8. 디버깅
9. 순서도에서 코드로 전환
10. 작은 프로젝트

현재 코딩 퍼즐은 정답 명령 문자열 하나만 비교하지 않습니다. 명령을 실제 보드에서 실행해 장애물 충돌, 보드 이탈, 목표 도착, 최단 경로 여부를 평가합니다. 목표에는 도착했지만 최단 코드가 아니면 부분 점수로 제출할 수 있고, 더 짧은 코드로 다시 도전할 수도 있습니다.

### CT

CT는 문제 해결 과정의 계열성을 둡니다.

순서:

1. 현재 상태와 목표 상태 보기
2. 문제를 작은 부분으로 나누기
3. 비슷한 모양 찾기
4. 필요 없는 정보 줄이기
5. 순서 만들기
6. 반복되는 부분 줄이기
7. 선택 조건 만들기
8. 순서도에서 코드로 보기
9. 두 방법 비교하기
10. 자동화 관점으로 보기

### AI 기초

AI는 엄격한 알고리즘 순서보다 문제 해결 방식의 변화가 보이게 구성합니다.

권장 흐름:

1. 사람이 규칙을 정하는 문제
2. 컴퓨터가 많이 시도해 보는 문제
3. 좋은 경로를 찾는 문제
4. 데이터를 보고 분류하는 문제
5. 예시를 보고 예측하는 문제
6. 틀린 결과를 고치는 문제
7. AI가 잘하는 일과 어려워하는 일 구분

AI 기초는 MVP 이후 영역입니다. 처음부터 무리하게 촘촘한 계열성을 만들 필요는 없습니다.

### STEAM

STEAM은 프로젝트형 구성이 어울립니다.

권장 흐름:

1. 관찰
2. 조작
3. 측정
4. 기록
5. 비교
6. 예측
7. 만들기
8. 설명하기

STEAM은 주제별 선택형으로 두고, ICT와 연결되는 조작만 선행 조건으로 둡니다.

현재 프로토타입에는 가져온 AI Studio 활동을 `AI Studio STEM 실험실`로 묶어 연결합니다. 태양계, 우주 탐험, 주사위 누적 합계, 학생 데이터, 리듬 반응 게임을 같은 프레임에서 실행하고, 개별 활동의 내부 CSS는 공통 폰트와 둥근 정도가 맞도록 보정합니다.

### 가치와 AI 윤리

가치 영역은 정답형 계열성보다 판단 경험의 폭을 넓히는 방식이 적합합니다.

권장 흐름:

1. 나의 선택
2. 친구의 입장
3. 개인정보
4. 공정함
5. 안전
6. 책임
7. 편향
8. 설명 가능성
9. 딜레마 판단
10. 나만의 행동 원칙 만들기

이 영역은 학생 수준에 맞게 순서를 조정할 수 있습니다.

현재 프로토타입의 AI 성향 딜레마 랩은 가져온 `AI 어린이 판사` 활동으로 대체해 연결합니다. 플랫폼 내부의 임시 딜레마 구현은 남겨둘 수 있지만, 학생이 진입하는 기본 VALUE 활동은 외부 HTML을 공통 미션 프레임에서 실행합니다.

## 무리하지 않을 기준

계열성을 만들 때 다음에 해당하면 억지로 순서를 고정하지 않습니다.

- 앞 단계를 몰라도 충분히 해 볼 수 있는 활동
- 토론형, 선택형, 가치 판단형 활동
- 교과 주제에 따라 순서가 바뀌는 활동
- 학생 흥미에 따라 먼저 경험해도 되는 활동

이 경우에는 필수 선행 단계가 아니라 추천 경로로 표시합니다.

## 개발 적용 방식

각 미션에는 다음 정보를 둡니다.

- 영역
- 모듈과 내부 라운드
- 새로 배우는 조작 또는 개념
- 선행 미션
- 추천 미션
- 난이도
- 필요한 입력 방식
- 힌트 유형
- 완료 조건

프론트엔드 프로토타입에서는 이 정보를 JSON 데이터로 두면 충분합니다. 백엔드가 붙으면 같은 구조를 서버 데이터로 이전할 수 있습니다.
