# 게임 중심 설계

## 핵심 방향

디지터시는 게임을 곁들인 학습지가 아니라, 조작 자체가 플레이가 되는 웹앱입니다. 학생은 설명을 오래 읽고 문제를 푸는 것이 아니라, 가상 컴퓨터 안에서 작은 목표를 직접 조작하며 체험합니다.

## 기본 게임 루프

1. 짧은 상황과 목표가 제시된다.
2. 학생이 하나의 조작을 수행한다.
3. 화면이 즉시 반응한다.
4. 성공하면 작은 시각효과가 나온다.
5. 같은 조작 또는 연결 조작이 다른 맥락에서 다시 나온다.
6. 모듈을 마치면 클리어 효과와 배지를 받는다.

이 루프는 ICT뿐 아니라 CT, AIT, STEM, VALUE 모듈에도 적용합니다.

## 모듈 맵

전체 학습은 숫자 단계가 아니라 대영역별 모듈 맵으로 보여줍니다.

| 대영역 | 플레이 성격 |
| --- | --- |
| ICT | 직접 조작과 반복 숙달 |
| CT | 퍼즐, 순서, 시각화 |
| AIT | AI 관점 변화와 기술 흐름 체험 |
| STEM | 조절, 실험, 예측 시뮬레이션 |
| VALUE | 딜레마 선택과 가치 성향 확인 |

학생은 모듈 카드를 선택해 체험으로 들어갑니다. 교사는 같은 맵을 통해 어느 대영역과 모듈이 완료되었는지 봅니다.

## 반복 숙달

한 번의 성공은 우연일 수 있습니다. 그래서 모듈 내부에는 짧은 라운드를 두고, 같은 능력을 다른 상황에서 다시 쓰게 합니다.

예시:

- 기능 조작 체험: 이동 -> 클릭 -> 드래그 -> 입력
- OS 동작 체험: 앱 실행 -> 작업 -> 저장 -> 파일 이동
- 타자연습: 단어 -> 띄어쓰기 포함 표현 -> 짧은 문장

## 보상

보상은 학생 간 경쟁보다 숙달과 수집 중심으로 설계합니다.

추천 보상:

- 배지
- 스티커
- 바탕화면 꾸미기 아이템
- 모듈 완료 연출
- 다음 체험 추천

피해야 할 보상:

- 학생 간 공개 랭킹
- 과도한 시간 압박
- 실패 횟수 낙인
- 학습 목표와 무관한 랜덤 보상 남발

## 피드백

피드백은 짧고 즉시 나와야 합니다.

성공 피드백:

- "좋아요. 다음 체험으로 넘어갑니다."
- "앱이 열렸습니다."
- "파일이 바탕화면에 생겼습니다."

실패 피드백:

- "목표 영역 안까지 끌고 가서 놓아보세요."
- "시작과 목표 확인이 들어가야 실행할 수 있어요."
- "다른 사람의 정보와 안전을 한 번 더 생각해봅니다."

실패 피드백은 학생을 평가하지 않고 다음 행동을 알려줍니다.

## 가이드 시스템

일정 시간 반응이 없으면 가이드가 단계적으로 개입합니다.

1. 조작 대상을 강조한다.
2. 목표가 되는 버튼, 입력칸, 드래그 대상을 알려준다.
3. 그래도 어렵다면 따라하기 버튼으로 현재 목표를 다시 표시한다.

## 게임 UX 원칙

1. 첫 행동까지 오래 기다리게 하지 않는다.
2. 한 라운드에 새 조작을 두 개 이상 넣지 않는다.
3. 목표물은 초등학생이 놓치지 않을 만큼 크게 만든다.
4. 클릭 가능한 것과 아닌 것을 시각적으로 구분한다.
5. 실패는 게임 진행의 일부로 보이게 한다.
6. 반복은 같은 화면 복붙이 아니라 상황 변주로 만든다.
7. 모듈 맵에서 현재 위치와 다음 체험이 항상 보이게 한다.
