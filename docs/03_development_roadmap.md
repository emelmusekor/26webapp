# 개발 로드맵

## 0. 제품 기준 정리

목표:

- 디지터시 개념 정의
- 5대 대영역과 모듈 구조 확정
- 메인 플랫폼과 개별 프로그램의 책임 분리
- 학생 체험과 교사용 진행 확인 흐름 정의

산출물:

- 프로젝트 의도 문서
- MVP 범위 문서
- 학습 모듈 구조 문서
- 플랫폼 아키텍처 문서

## 1. 메인 플랫폼 프로토타입

목표:

- 학생이 하나의 플랫폼 맵에서 각 모듈로 들어갈 수 있게 한다.
- 모듈 상세, 시작 버튼, 미션 오버레이, 가이드 콘솔을 제공한다.
- 진행 기록과 배지를 브라우저 로컬 저장으로 검증한다.

필수 기능:

- 대영역별 모듈 맵
- 가상 컴퓨터 바탕화면 탭
- 배지 보드
- 간이 교사용 진행 보기
- 무응답 힌트
- 라운드 성공 효과와 모듈 클리어 효과

## 2. ICT 우선 구현

목표:

- 초등학생이 가장 먼저 필요한 ICT 기초 조작을 반복 숙달한다.

필수 모듈:

- 기능 조작 체험
- OS 동작 체험
- 타자연습

완료 기준:

- 각 모듈이 여러 라운드로 구성된다.
- 우연한 성공을 줄이는 완료 조건을 둔다.
- 학생이 멈추면 가이드가 개입한다.

## 3. CT 확장

목표:

- 컴퓨팅 사고를 문제 해결 놀이로 경험하게 한다.

필수 모듈:

- code.org 수준의 코딩 퍼즐
- 순서도에서 코드 보기
- 언플러그드 컴퓨팅 시각화 놀이
- 첨부 Interactive Challenge 연결

## 4. AIT, STEM, VALUE 확장

목표:

- AI 기술, 융합 실험, 가치 판단 모듈을 플랫폼 안에 연결한다.

필수 모듈:

- AI 패러다임 게임 연결
- 노드 기반 AI 흐름 실습 연결
- 우주 탐사대 자리
- AI 기술 흐름 시각화
- 핀테크 체험
- AI와 함께하는 신약 개발 실험
- 모션 코딩 자리
- AI 성향 딜레마 랩
- Gemini 기반 AI 가치 실습 링크

## 5. 전문 개발자 인수인계

목표:

- 프론트엔드 구조를 백엔드 개발자가 이어받기 쉽게 정리한다.

인수인계 포인트:

- `platform/data/catalog.js`: 모듈 메타데이터의 단일 출처
- `platform/modules/registry.js`: 모듈 타입과 렌더러 연결 지점
- `platform/core/storage.js`: 서버 저장소로 교체할 경계
- 외부 프로그램 폴더: 메인 플랫폼과 분리 유지

## 기술 방향

현재 프로토타입은 정적 HTML, CSS, ES 모듈 JavaScript로 구성합니다. 운영 개발 단계에서는 React 또는 Next.js로 이전할 수 있지만, 지금은 기획 검증과 상호작용 품질이 우선입니다.

백엔드는 전문 개발자가 이어받을 영역으로 두며, 초기에는 로컬 저장과 샘플 데이터만 사용합니다.
